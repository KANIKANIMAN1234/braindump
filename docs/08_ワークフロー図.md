## 2. LIFF 認証フロー

```mermaid
sequenceDiagram
    actor User as 👤 ユーザー
    participant Browser as ブラウザ（LIFF）
    participant LINE as LINE 認証サーバー
    participant API as Vercel API
    participant LINE2 as LINE /v2/profile

    User->>Browser: アプリにアクセス
    Browser->>Browser: ローディングオーバーレイ表示
    Browser->>Browser: liff.init()
    alt 未ログイン
        Browser->>LINE: liff.login()（リダイレクト）
        User->>LINE: LINEアカウントで認証
        LINE-->>Browser: 認証コード → アクセストークン発行
    end
    Browser->>Browser: liff.getAccessToken()
    Browser->>Browser: liff.getProfile()
    Browser->>Browser: ヘッダーにアイコン・名前表示
    Browser->>API: GET /api/messages\nAuthorization: Bearer <token>
    API->>LINE2: GET /v2/profile（token検証）
    LINE2-->>API: { userId, displayName, ... }
    API-->>Browser: チャット履歴（直近12時間）
    Browser->>Browser: ローディングオーバーレイ非表示
    Browser->>Browser: 履歴表示 or ウェルカムメッセージ
```

## 3. 通常チャット（AI処理）フロー

```mermaid
sequenceDiagram
    actor User as 👤 ユーザー
    participant Browser as ブラウザ
    participant ChatAPI as POST /api/chat
    participant LINE as LINE /v2/profile
    participant OpenAI as gpt-4o-mini
    participant Supabase as Supabase DB

    User->>Browser: メッセージ入力 → 送信 or 音声入力
    Browser->>Browser: タイピングインジケーター表示
    Browser->>ChatAPI: POST /api/chat\n{ message }\nAuthorization: Bearer <token>
    ChatAPI->>LINE: token検証
    LINE-->>ChatAPI: { userId }
    ChatAPI->>OpenAI: gpt-4o-mini\n+ システムプロンプト\n+ 8種のツール定義\n+ ユーザーメッセージ
    OpenAI-->>ChatAPI: ツール呼び出し指示\n{ tool_name, args }
    ChatAPI->>Supabase: ツール実行\n（.eq("line_user_id", userId) でフィルタ）
    Supabase-->>ChatAPI: 実行結果
    ChatAPI->>OpenAI: ツール実行結果を送信
    OpenAI-->>ChatAPI: 最終応答テキスト
    ChatAPI->>Supabase: chat_messages にINSERT\n（user / bot の両メッセージ）
    ChatAPI-->>Browser: { reply, tasks? }
    Browser->>Browser: タイピングインジケーター非表示
    Browser->>Browser: ボットメッセージ表示
```

## 4. タスク管理ワークフロー

### 4.1 タスク追加

```mermaid
flowchart TD
    A([タスク追加ボタン or 自然言語]) --> B{入力方式}
    B -->|ガイドフロー| C[タスク名入力\nSTATE: TASK_ADD_NAME]
    B -->|自然言語| L[POST /api/chat\n自然言語解析]

    C --> D[期日入力\nSTATE: TASK_ADD_DUE\n例: 2026-06-01 or なし]
    D --> E[優先度選択\nSTATE: TASK_ADD_PRIO\n高 / 中 / 低 ボタン]
    E --> F[POST /api/chat\nadd_task ツール実行]
    L --> F

    F --> G{バリデーション\npriority チェック}
    G -->|有効: 高/中/低| H[Supabase INSERT\ntasks テーブル\nline_user_id 付与]
    G -->|無効値| I[中 に補正]
    I --> H

    H --> J([ボット: 登録完了メッセージ])
```

## 6. 音声入力ワークフロー

```mermaid
flowchart TD
    A([🎤 ボタンタップ]) --> B{isRecording}
    B -->|false → 録音開始| C[finalTranscript = 空\nrecognition.start\nisRecording = true\nボタン: 赤・パルスアニメーション]
    B -->|true → 録音停止| D[isRecording = false\nrecognition.stop\nボタン: 通常色に戻る]

    C --> E{音声検知}
    E -->|発話中| F[onresult イベント\ninterim → テキストエリアにリアルタイム表示\nfinal → finalTranscript に蓄積]
    F --> E

    E -->|無音（ブラウザが停止）| G[onend イベント]
    G --> H{isRecording?}
    H -->|true: まだ録音中| I[recognition.start 自動再起動\n→ 連続録音継続]
    H -->|false: 停止済み| J[終了・ボタン通常色]
    I --> E

    D --> K[テキストエリアに確定テキスト残る]
    K --> L([→ 送信ボタンで送信])
```

```mermaid
sequenceDiagram

    participant MsgAPI as GET /api/messages

    Browser->>Browser: 日付セパレーター挿入\n各メッセージをチャットに表示
```

## 8. データ分離（マルチユーザー）の仕組み

```mermaid
flowchart LR
    subgraph UserA["ユーザーA（LINE userId: Uaaaa...）"]
        TokenA[アクセストークンA]
    end
    subgraph UserB["ユーザーB（LINE userId: Ubbbb...）"]
        TokenB[アクセストークンB]
    end

    subgraph API["Vercel API"]
        Verify{LINE /v2/profile\nで token 検証}
        Filter[.eq line_user_id\nでデータ絞込]
    end

    subgraph DB["Supabase DB"]
        RowA1["tasks: Uaaaa... タスクX"]
        RowA2["tasks: Uaaaa... タスクY"]
        RowB1["tasks: Ubbbb... タスクZ"]
        RowC1["insights: Uaaaa... 気づき1"]
        RowC2["insights: Ubbbb... 気づき2"]
    end

    TokenA -->|Bearer| Verify
    TokenB -->|Bearer| Verify
    Verify -->|userId取得| Filter
    Filter -->|Uaaaa...のみ参照可| RowA1
    Filter -->|Uaaaa...のみ参照可| RowA2
    Filter -->|Ubbbb...のみ参照可| RowB1
    Filter -.->|アクセス不可| RowB1
    Filter -.->|アクセス不可| RowA1
```

*ユーザーAは自分のデータ（Uaaaa...）のみ参照・更新できます。他ユーザーのデータには一切アクセスできません。*

## 8. B2B マルチテナント（2026-05-30）

```mermaid
flowchart LR
    Ops[運営] --> PC[platform-console.html]
    PC -->|POST organizations| APIP[/api/platform/*]
    APIP --> DB[(organizations / members / invites)]

    Rep[代表] -->|招待URL| LIFF[LIFF + activate]
    LIFF --> Auth[/api/auth/activate]
    Auth --> DB

    Rep --> Wiz[⚙️ 組織ウィザード 0〜3段]
    Wiz -->|POST setup 1回のみ| Org[/api/org/setup]
    Org --> DB

    User[メンバー] --> App[index.html]
    App -->|GET tasks| Tasks[/api/tasks + data-scope]
    Tasks --> DB
```

- **0段:** ウィザードのみ → 招待・⚙️ なし
- **org_admin:** `organization_id` で法人内全タスクを一覧可能
