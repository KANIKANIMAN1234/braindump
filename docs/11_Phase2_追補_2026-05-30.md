## 2. 組織階層「0段（代表者のみ）」

### 2.1 定義

| 項目 | 内容 |
|------|------|
| `org_structure_depth` | `0`（`organizations` 制約: `0, 1, 2, 3`） |
| 意味 | 部門・本部などの `org_units` を作らず、**代表管理者（org_admin）のみ**で法人を運用 |
| SQL | 既存 DB は `SQL/phase2_depth0.sql` を実行。新規は `phase1_multi_tenant.sql` に 0 が含まれる |

### 2.2 代表管理者の操作

1. 招待 URL で LINE 登録（Phase 1）
2. アプリ右上 **⚙️** → ウィザードで **「0段（代表者のみ）」** を選択
3. 利用規約同意 → 保存 → 法人 `status` が `active`
4. **メンバー招待は不可**（ウィザード・招待 UI なし）
5. 設定完了後、**⚙️ ボタンは非表示**（`org-admin.js`）

### 2.3 UI 不具合対応（0段選択時）

| 事象 | マスクのみ残りパネルが表示されない |
|------|----------------------------------|
| 対応 | オーバーレイに `is-open` クラスで表示制御、レイアウト・バックドロップ操作を修正（`app/org-admin.js` / `app/style.css`） |

## 6. タスク一覧とデータスコープ

### 6.1 タスク一覧の取得経路（変更）

| 以前 | [📋 タスク一覧] → AI チャット経由で一覧 |
|------|----------------------------------------|
| **現在** | `showTaskList()` → **`GET /api/tasks`** 直取得 → `addTaskListMessage()` |

ガイドフロー（完了・優先度・期日修正）も従来どおり `/api/tasks` を使用。

### 6.2 `lib/data-scope.js` の閲覧範囲

| ロール | tasks / insights / chat_messages |
|--------|----------------------------------|
| `legacy`（members 未登録） | `line_user_id` のみ |
| `member` | 自分のレコード（法人内＋`organization_id` 未設定の移行データ） |
| `dept_admin` / `unit_admin` | 配下 `org_unit_id` ＋ 自分 |
| **`org_admin`** | **`organization_id` が一致する法人内の全レコード**（他メンバーの `line_user_id` も含む） |

INSERT 時は `scopedRowData()` で `organization_id` / `org_unit_id` / `member_id` を付与。

### 6.3 移行データの扱い

| 状況 | クエリ |
|------|--------|
| `organization_id` が NULL の旧タスク | 同一 `line_user_id` なら「自分のタスク」として OR 条件に含める |
| Phase 2 導入後 | `SQL/phase2_backfill_task_org.sql` で業務テーブルへ `organization_id` を付与推奨 |

## 7. 認証 API の追補

### 7.1 `POST /api/auth/activate`

| 処理 | 内容 |
|------|------|
| `line_user_id` | 保存前に **trim**（改行・空白除去） |
| 再登録 | `status=invited` かつ手動で `line_user_id` が入っている場合の再紐づけを許可 |
| 代表登録 | **必ず招待 URL から**（DB への代表 `line_user_id` 手入力は運用禁止） |

### 7.2 `GET /api/auth/me`

| 処理 | 内容 |
|------|------|
| `line_user_id` | 応答前に trim |
| `organization` | `organizations` を単体取得し `name` 等を返す（ヘッダー企業名用） |
| 未登録 | `legacy: true`（従来の個人利用と同様） |

### 7.3 メンバーが API で認識される条件

| 項目 | 必須値 |
|------|--------|
| `members.status` | **`active`**（`invited` のままではタスク API が正しく動かない） |
| `members.line_user_id` | LIFF の `userId` と**完全一致**（改行 `\r\n` なし） |

## 9. トラブルシューティング（本番で確認済み）

### 9.1 タスク一覧が空になる

| 原因 | 確認・対処 |
|------|------------|
| `members.status` が `invited` | `active` に更新し `activated_at` を設定 |
| `line_user_id` に改行・空白 | `trim` した値に更新（`phase2_fix_line_user_id.sql` 2a-pre 参照） |
| タスクに `organization_id` なし | `phase2_backfill_task_org.sql` を実行 |
| 一覧を AI のみで取得していた | フロントを `/api/tasks` 直取得に修正済み（`main.js`） |
| org_admin なのに自分の ID のみ見ている | `data-scope.js` で法人全体スコープに修正済み |

### 9.2 チャット履歴とタスク一覧の違い

| 機能 | スコープ |
|------|----------|
| チャット履歴（12時間） | `chat_messages` に **スコープ適用**（法人管理者は法人内の bot/user メッセージが混在しうる） |
| タスク一覧ボタン | `/api/tasks` のみ（上記スコープ） |

### 9.3 代表者の登録方法

| OK | 運営コンソールで発行した **招待 URL** から `auth/activate` |
| NG | Supabase で `members.line_user_id` を手入力（改行混入・status 未更新の原因になりやすい） |
